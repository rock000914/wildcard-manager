# Wildcard Manager

Stable Diffusion のワイルドカードを一元管理するデスクトップアプリです。増え続ける `.txt` ワイルドカードの整理・検索・サムネイル管理・新規作成までを、単一の GUI 上で完結させます。

## できること

### 基本操作
- `txt` ワイルドカードの読み込み・編集・保存
- フォルダツリーによる絞り込み
- ファイル名・本文・カスタムタグ・LoRA 名での横断検索
- LoRA タグを含む / 外してのコピー切替
- `sd-dynamic-prompts` / `wildcard-gallery` からライブラリへのコピー・移動
- カスタムタグによる分類（各 txt と同名の `.wcm.json` に保存）
- 右クリックメニューからのカード名リネーム
- シフトクリックによる矩形範囲選択（Windows エクスプローラー風の複数選択）

### サムネイル
- ワイルドカード一覧へのサムネイル表示
- StabilityMatrix / Forge 系 `sdapi` を使ったサムネイル生成 →  `.webp` 保存
- 既存画像をそのままサムネイルに登録（カード右クリック／`ツール(T)` → 「サムネイルに画像を指定...」）
- 1枚のカードに複数画像（2枚目・3枚目…）を登録（「サムネイルに画像を追加...」）
- カードのダブルクリックでめくりアニメーション付きで次の枚へ（右下の `2/3` ピルが枚数表示。Ctrl+ダブルクリックは従来どおり全文コピー）
- カードを消さずにサムネイル画像だけゴミ箱へ移動（複数枚カードは右クリック「サムネイルを削除...」→**枚名で直接選択**、1枚カードは「このサムネイルを削除...」／「サムネイルをすべて削除...」）
- 不足サムネイルの一括生成（バックグラウンドスレッドで UI をブロックしない）
- 生成時にランダムなワイルドカードを組み合わせて多様なプレビューを作成

### 新規ワイルドカード作成
- キャラクタータブ + 動的カスタムタブ（「+」ボタンで追加）
- 衣装ごとのプロンプトをまとめて作成・管理
- ダイアログ内でのサムネイルプレビュー生成
- LoRA タグの色分け表示（使用中の LoRA が一目でわかる）
- タグ削除モード（ボタン色・枠線色の変化で状態を明示）

### API 連携
- sd-webui API 接続テスト（JSON 応答検証つき）
- チェックポイント一覧の取得
- 生成状態のリアルタイム監視（API ステータスインジケーター表示）
- ADetailer 対応

## 保存構造

```
library/
├── wildcards/          # wildcard 本体（txt ファイル）
│   ├── Position/
│   │   ├── character1.txt
│   │   └── character1.txt.wcm.json  # カスタムタグ
│   └── ...
├── thumbnails/         # サムネイル（webp ファイル）
│   ├── Position/
│   │   ├── character1.preview.webp   # 1枚目
│   │   └── character1.g2.webp        # 2枚目以降（.g3, .g4 …）
│   └── ...
wildcard_manager.db     # SQLite インデックス（高速化用）
config.json             # 設定
ui_state.json           # UI 状態（ソート・分割バー位置等）
```

## セットアップ

### 必要なもの
- Python 3.10+
- PySide6
- Pillow
- requests

### インストール

```powershell
pip install PySide6 Pillow requests
```

### 起動

```powershell
python app.py
```

## 初回設定

1. `設定` タブで以下を確認・入力:
   - **管理ルート**: wildcard の保存先（デフォルト: `library/wildcards`）
   - **サムネイルルート**: サムネイルの保存先（デフォルト: `library/thumbnails`）
   - **API ベース URL**: sd-webui の API（デフォルト: `http://127.0.0.1:7860`）
   - **移行元パス**: 既存の `sd-dynamic-prompts` や `wildcard-gallery` のパス
2. `再読込` でライブラリをスキャン

#### ライブUI修正2（ユーザー指摘2点）
- **BaseModelフィルタの見出しから「LoRAの」を削除**: 「LoRAのBaseModelで絞り込み」→「**BaseModelで絞り込み**」（ユーザー指摘「loraのbasemodelの絞り込み、loraのがいらない」）。この欄はカード一覧全体にかかるフィルタで、修飾語の「LoRAの」は対象を二重に言及する冗長表記だった。コンボの中身は変更しない（`すべて` ＋ ベースモデル9種 ＋ `LoRAなし` の計11項目を実機で確認。`LoRAなし`=`__nolora__` は「ベースモデル情報が無いLoRAだけを出す」絞り込みとして機能しているため残置）
- **フォルダツリーのホバー帯を行全体に**: `::item:hover` 規則が1つも無かったため、Qt は**枝葉セル（branch）にだけ既定の薄い四角**を描き、行本体は明るさが変わらない。インデント帯に浮く小さな灰色箱が「マウスホバーのハイライトがおかしい」の正体（選択行の「||」と同じ系統の欠陥）。`QTreeView#folderTree::item:hover`（`HOVER_BG`・`border-radius:0`）と `QTreeView::branch:hover` を追加して行全体を一枚帯にし、`#folderTree::item:selected:hover` のほうが優先度が高いことを利用して**選択行にホバーしても選択色を維持**（薄まらない）
- 実測（`.tmp/hover_probe.py`＝実アプリ／実カーソル、`.tmp/qss_hover_check.py`＝同じQSSを孤立させた3項目チェック）: ホバー行は x=3..297（画像幅315、右端15pxはスクロールバー）まで連続した `#29384a` の帯、高さ35実ピクセル = 行高28論理px × DPR1.25。選択行にホバーした状態では `HOVER_BG` の帯は0行で `SELECTED` 帯のみ。合成 `QHoverEvent` では `:hover` が発火しない（`State_MouseOver` が立たない）ので実カーソル移動が必須

#### 既存画像をサムネイルに登録する機能を追加（ユーザー質問「すでにある画像をサムネイルに登録する機能ってあったけ？」への回答）
- 質問時点の実態: **新規作成ダイアログにだけ有った**（「画像を選択」`_pick_thumb` と、ダイアログへの画像D&D → 保存時に `ensure_thumbnail_destination` へ `copy2`）。**既存カードに対する登録手段は無く**、メニューは「サムネイルを生成」「不足サムネイルを一括生成」、カード右クリックは「サムネ生成」「サムネフォルダを開く」だけ（ライブラリ取込が `resolve_thumbnail_from_roots` で既存サムネを従える間接経路はある）
- **カード右クリックに「サムネイルに画像を指定...」を追加**（`ツール(T)` メニューにも同じ項目＝現在カードへ作用）。既存画像をAPI生成を使わずそのままサムネイルにできる。保存先・形式は生成と完全に揃える（`{thumbnail_root}/{rel.parent}/{stem}.preview.webp`、`WEBP quality=82 method=6`）ので、生成済みサムネイルの後の差し替えも表示優先度を壊さない
- 長辺は `THUMBNAIL_ASSIGN_MAX = 1024px` 以内に縮小（一覧の表示上限は720pxなのでそれ以上の解像度はファイルだけ膨らませる）。既存サムネイルがある場合は**上書き確認**を出し、拒否時はファイルもUI更新も触らない
- 反映は生成時と同じ経路: `repo.refresh_entry()` でDBと `has_thumbnail` / `thumbnail_path` を更新 → `_replace_entry()` でカードアイコンと右パネルのプレビューを即時更新
- 検証（`.tmp/assign_thumb_probe.py`＝合成ライブラリ、実データは触らない）: **14項目PASS** — キャンセル無影響、`preview.webp` 生成、WEBPとして読める、2000x1500 → 1024x768、`_replace_entry` 呼び出し、`has_thumbnail=True` と `thumbnail_path==dest`、上書き拒否時は中身不変・追加更新なし、上書き承認時は中身入替と600px維持、`entry=None` で安全終了

#### 2枚目以降のサムネイル・めくりアニメ・サムネイルのみ削除（ユーザー依頼「遊びの機能を入れる」）
- **1カード複数画像**: 2枚目以降は `{stem}.g2.webp` / `{stem}.g3.webp` …（`GALLERY_MARKER=".g"`）。区切りを `_` にしなかったのは、`{stem}_2` だと**別カード `foo_2.txt` の1枚目と実パス衝突する**ため。フォルダ単位の索引（`build_thumbnail_gallery_index`）を1回作って全カードに使い回すので、描画のたびに走査することはない
- **ダブルクリックでめくる**: 2枚以上のカードはダブルクリック＝次の枚（`CardFlip`）。1枚のみのカードは従来どおり全文コピー、多画像カードでも **Ctrl+ダブルクリック＝コピー**で既存手順を失わない
- **めくりの画法**: 横縮みを `|cos(pi t)|`（縦軸まわり回転を真横から見た射影）、影を `120*sin(pi t)` の黒オーバーレイ。`t<0.5` で旧画像・`t>=0.5` で新画像を描くので「裏返って別面が出る」動きになる。アニメ本体は `QPropertyAnimation(progress)`／InOutSine／340ms（`FLIP_DURATION_MS`）
- **枚数ピル**: 2枚以上のカード右下に `2/3`。めくれるカードはダブルクリックでめくれること自体が否則発見されない（おまけは存在が見えて初めて使われる）
- **サムネイルだけ削除**: カード右クリック「このサムネイルを削除...」（表示中1枚）／「サムネイルをすべて削除...」（全枚）、`ツール(T)` →「表示中のサムネイルを削除...」。`QFile.moveToTrash` で**ごみ箱経由＝復旧可能**にし、`.txt` 本体は触らない。削除後は枚番号がずれる（g2だけ消えると g3 が2枚目になる）ので `forget_thumbnail()` で枚目・アイコンキャッシュ・フォルダ索引をまとめて忘れ、保護パス（生成直後3秒）も無視して再ロードさせる
- **1枚目の欠落にも耐える**: DBが解決した1枚目は常に先頭に置くが、そのファイルが消えていれば `{stem}.g2.webp` が先頭になって枚ずれしない。1枚目すら無いカードへ「追加」すると g2 ではなく `preview.webp` に書く（枚数の穴を作らない）
- **消す枚をめくり合わせなくてよい**: 2枚以上のカードは右クリックが「サムネイルを削除...」**サブメニュー**になり、`1枚目: xxx.preview.webp` / `2枚目: xxx.g2.webp（表示中）` … のように枚名で直接選べる（1枚カードは従来どおり「このサムネイルを削除...」1項目）。`delete_thumbnail_image(entry, page_index=N)` は0起点で枚を指定し、範囲外なら「N枚目は存在しません（現在 M 枚）」の案内だけ出してファイルには触らない。表示中1枚だけを消す方式だと「目的の枚へめくって合わせる」手順が隠れ、誤削除をごみ箱あけの手間に転換してしまう
- **パスの大小文字違いで枚数を二重に数えていた**（ユーザー指摘「なんかカードのサムネイル細くない？」の実体）: DBは `H:\...`、`config.json` 由来のサムネイル根は `h:\...` で、Windows では同じファイルなのに `==` / `in` 比較だと別物扱い。**実データ7575枚（サムネイルのあるカード全件）が `preview.webp` 1枚なのに `1/2` ピルを出ていた**（＝全カードの右下がめくれる扱いに見え、ピルが画像に重なって細く見える）。実パス比較を `thumbnail_paths_equal()`（`os.path.normcase`）に統一し、枚数・「表示中」マーク・削除対象の枚引当をすべてこの関数で比べるようにした
- 検証（`.tmp/gallery_flip_probe.py`＝合成ライブラリ・一時ディレクトリ、実データは触らない）: **91項目PASS** — 索引发動（preview→plain→g2,g3,g10 の**数値順**／`_g2` は別カードの1枚目／g0・g1 は枚番号に数えない／無いフォルダは空）、`next_gallery_slot` の空きスロット探索、`gallery_paths` の3枚・先頭preview、枚目0の**走査なし高速路**、枚数超過のclamp、1枚のみカードは `flip_to_next` が None、2→3→1 のラップ、めくり中は `flips` に入り完了後に抜けてアイコンが差し替わる（実ピクセルで2枚目の緑を確認）、`pixmap_for` の横縮み（t=0 全幅100 → t=0.5 で6px → t=0.9 で95px）・影・旧新の取り違えなし、`invalidate_gallery` が同一フォルダの他カードcacheも捨てる、1枚目欠落時に g2 が先頭、追加（1枚目欠落→preview／2枚目→g2／上限内WEBP）、削除（表示中1枚のみ／拒否時はゴミ箱移動を試みない／all_pages で全枚／カードは残る／0枚時は案内のみ）、ダブルクリックの意味（多画像＝めくってコピーしない／Ctrl＝枚目を動かさずコピー／1枚のみ＝従来コピー）、**ピル描画は撮り比較**（同じカードの1枚状態と3枚状態で `view.grab()` を差分し、差分が右端付近・サムネイル下端帯の 35x21 実ピクセルだけ／1枚カードの面は差分ゼロ）、**枚指定削除のサブメニュー**（2枚カードで3枚が並び表示中に印／サブメニューの「3枚目」を実トリガすると表示中の2枚目ではなく g3 だけがゴミ箱へ／残り2枚で番号が詰まり枚目は1枚目へ戻る／`page_index=9` は案内のみでファイル非接触／1枚カードはサブメニューが出ない）、**ケース違いパス**（`H:\` と `h:/` を同一ファイルと見て1枚は1枚／2枚は2枚／ピル条件が偽／「表示中」が正しい枚に付く）。H群は比較を修復前の素の `==` に戻したミューテーションテストで **5項目FAIL（1枚→2枚、2枚→3枚）** になることを確認済み＝検査が実際にこの不具合を捕まえる。実データの件数は `.tmp/thumb_dup_audit.py`（読み取り専用）で実測。**クロップ群（I）**＝2:3素材を box いっぱいに切り出してサイズ一致、中央の正方形が 40x40 のまま（＝引き伸ばしなし）、上部の赤帯は残り下部の青帯は落ちる（顔位置優先）、横長素材も左右から切る、`decode_cover_image` の経路が worker と同一、カード寸法が `theme.CARD_ICON_RATIO` と一致

### v2.0 (2026-06-24) - 大規模改善リリース

外部レビューに基づくバグ修正・パフォーマンス改善・アーキテクチャ刷新。

#### バグ修正
- **コンテキストメニューの deleteLater バグ**: 右クリック→削除 で入力フィールド自体が消える重大バグを修正。`ui_utils.py` に委譲
- **数値パースのクラッシュ防止**: `int()` / `float()` の直接呼び出しを `_parse_int` / `_parse_float` ヘルパに置き換え。不正入力でも `ValueError` にならない
- **API 応答の誤検出防止**: プロキシや認証ページの HTML 応答（200 OK）を成功扱いしないよう、Content-Type が JSON かを追加検証
- **ファイル上書き時のデータロスト防止**: `unlink` → `move` の順序を廃止。`shutil.move` / `copy2` が直接上書きするように変更
- **パストラバーサル防止**: `move_entry` / `delete_folder` で `resolve()` 後に `library_root` 配下か検証。`../../etc` でライブラリ外へ脱出する問題を解消
- **LoRA タグ除去の正規化**: `.replace("  ", " ")` → `re.sub(r"\s+", " ", ...)` に変更。3連続スペースを正しく1つに潰す
- **LoRA 順序の保持**: `set` + `sorted` → `dict.fromkeys` で実出現順を保持
- **API 監視の未知 state 対応**: `_LAMP_COLORS.get(state, ...)` でフォールバック。未知の状態でも `KeyError` にならない
- **PathLabel の初期化保証**: 防衛的 `getattr` を削除。`_build_ui` で確実に初期化されるため直接アクセスに変更
- **dead code 削除**: `_pending_preview_request` / `_pending_content_abs_path` は書き込まれるだけで読み出されない変数だったため削除
- **Painter save/restore の整合**: `restore()` 呼び出し前に `save()` を追加。Qt の警告を防止
- **サムネイル反映の即時化**: 新規作成ダイアログで生成したサムネイルを `refresh_entry` で即座に DB に反映
- **サムネイルの重複生成防止**: 事前生成済みサムネイルをコピーする前に `dest.exists()` チェックを追加

#### パフォーマンス改善
- **サムネイル存在確認の O(1) 化**: 1ファイルずつの `exists()` → 事前ビルドした `set` でルックアップ。5,000 ファイルのライブラリで劇的改善
- **scan_library の単一パス化**: `rglob` + `sorted` → `os.walk` で1回の走査に。メモリ使用量も削減
- **SQLite PRAGMA の永続化**: `journal_mode=WAL` を毎回発行していたのを初回のみに。接続ごとのオーバーヘッド削減
- **PRAGMA 追加**: `synchronous=NORMAL` / `temp_store=MEMORY` / `cache_size=-2000` で書き込み速度とキャッシュ効率改善
- **dir_mtimes.json のデッドコード削除**: スキップ判定が `pass` だったため実質無効。毎回の二重ディレクトリ走査が不要に
- **不足サムネイル一括生成の QThread 化**: `processEvents()` ループを廃止。UI フリーズが解消
- **API 監視周期の延長**: 3秒 → 5秒。アイドル時の通信負荷軽減
- **コンテンツキャッシュの LRU 化**: `dict` → `OrderedDict`（上限 500 エントリ）。大規模ライブラリでのメモリ膨張を抑制
- **load_entries の最適化**: `SELECT *` → 必要カラムのみ。Python 側ソート → SQL で `GROUP BY` + `ORDER BY`
- **scan_profile.log のサイズ制限**: 1 MiB 超過時に古いエントリを切り詰め。ログの無限膨張を防止

#### アーキテクチャ改善
- **モジュール分離**: `main_window.py`（2,469行）から以下を独立モジュールに分離
  - `thumbnail_model.py`（422行）: サムネイル一覧のモデルとデリゲート
  - `thumbnail_workers.py`（151行）: サムネイル読込ワーカー
  - `tag_editor.py`（405行）: タグエディットウィジェット
  - `new_wildcard_dialog.py`（1,828行）: 新規ワイルドカード作成ダイアログ
  - `ui_utils.py`（116行）: ファイルマネージャー操作・コンテキストメニュー共通化
- **rel_path の UNIQUE 制約**: 重複行の自動解消。移行時に古い行を削除してから再作成
- **DB エントリ数の確認メソッド追加**: `db_entry_count()` / `count_txt_files_on_disk()` で整合性チェックが可能に

#### 機能追加
- **ランダム wildcard 組み合わせ**: サムネイル生成時に指定フォルダからランダムに wildcard を1つ選んでプロンプトに追加
- **ADetailer 対応**: `generation_adetailer_enabled` が True のとき `alwayson_scripts` に ADetailer を追加
- **API チェックポイント一覧取得**: `list_checkpoints()` で sd-webui のモデル一覧を取得
- **API 生成状態監視**: `check_progress()` / `is_generating()` でリアルタイムに進捗を確認

- **新規ワイルドカードダイアログの動的タブ**: 「+」ボタンでカスタムタブを追加可能。ダブルクリックでリネーム、右クリックで削除
